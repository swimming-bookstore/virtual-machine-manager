The signed ISO is not the disk that boots.

Quick start checks the Debian signature, then copies the installer. Two in-place edits on that copy start the text installer and answer it. The file Debian writes is the guest disk.

What firmware actually reads

Virtualization.framework has no CD drive, so boot.iso is a USB disk. EFI does not open the menu you see. It loads a tiny GRUB from the El Torito image, and that stub only runs source /boot/grub/grub.cfg. Editing the stub leaves the real menu waiting for a key.

Two edits, both in place

1. The menu does not wait

The largest /boot/grub/grub.cfg is the one both directory trees share. The text install entry is the one whose initrd is /install.amd/initrd.gz or /install.a64/initrd.gz, not the graphical gtk initrd. Its GRUB index becomes the default, and the timeout becomes 0.

set default=<text entry>
set timeout=0
menuentry 'Install' {
  linux /install.amd/vmlinuz auto=true priority=critical --- quiet
  initrd /install.amd/initrd.gz
}

The guide puts auto=true priority=critical before ---. Parameters after that dash are not installer questions. Timeout 0 is the GRUB form of “do not hit Enter”.

2. Answers ride in the text initrd

The guide’s initrd method is a file named preseed.cfg in the initrd root. The installer loads it by itself. The graphical initrd is left alone, so a wrong menu entry cannot see the answers.

initrd.gz
slack

ISO files occupy whole 2048-byte sectors. The unused tail of the last sector is enough for one more gzip member: a cpio archive of preseed.cfg plus TRAILER!!!. The directory size, little-endian and big-endian, grows by that many bytes. Nothing after the file moves, so the signature of the original ISO is irrelevant and the boot copy stays the same length.

What the answers decide

Language and keys US English, US keymap, UTC.
Network first interface, host debian.local, mirror deb.debian.org.
User account debian, root login off. The password is locked (!), so the install can finish unattended.
Disk one partition on /dev/vda, which is the virtio guest disk. GRUB is installed there too.
Packages tasksel does not run. The cdrom is not the apt source.
Finish no media check. A failed install stays on screen. When Debian, GRUB, and the host SSH key are on disk, the installer powers off. The host logs in, then snapshots the disk.

The other preseed disk

preseed.img is a 64 KiB FAT12 stick labeled PRESEED with the same file at its root. It is attached beside the installer. The boot line does not pass preseed/file=/hd-media/preseed.cfg. The copy inside the text initrd is the one the installer loads.

After the installer stops

The preseed does not trust the installer screen. late_command checks that /target/etc/debian_version and /target/boot/grub/grub.cfg exist, copies /authorized_keys into the debian account, enables sshd, and powers off. The host generates an ed25519 key in ssh/ and logs in on the guest's NAT address, port 22. VZNATNetworkDeviceAttachment takes no forwarding rules, so there is no host port 2222. The probe does not wait for the virtual machine state to read running, and it walks 192.168.64.2–254 after ARP, so a guest outside .2–.8 is not left on the SSH check. A black screen is not finished. A partition table is not a finished login either. Reopening a disk that already has one boots it alone, still inside the popup, and waits for that same login. The host snapshots the disk only after that key logs in.

The snapshot is taken once, after the guest has stopped, so it is the installed system and not a half-written disk. New Debian machines are clones of that directory. On APFS the clone shares blocks with the snapshot, so creating another machine does not copy 16 GiB. Reopening the app does not start the installer virtual machine again. That disk stays shut down. Quick start does not show the installer thumbnail, the Show installer button, or Start Debian. New machines come from the snapshot.

While preseed is running, the guest has a keyboard and no pointer. Quick start moves to the second page for this step. That page is only prepare the preseed disk, then patch the installer copy. Back and Next move between the download page, that page, and Debian setup. Leaving setup does not stop the guest. The ISO bar is a small thumbnail of the installer, with a Show installer button on the right. That button opens the guest in a new window and leaves the thumbnail in place. Neither the thumbnail nor that window captures the mouse or the keyboard, and Quick start never attaches a pointer, including the SSH check after the installer stops. The rows under the thumbnail are the installer, the guest disk, the SSH login, and the snapshot. A clone window is the one that captures. When the guest stops before the snapshot is saved, Start Debian boots disk.img alone so the host can log in. After the snapshot, that button is gone. That file, next to nvram.bin, is the installed system.
